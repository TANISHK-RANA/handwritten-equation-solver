% ABSTRACT

\begin{abstract}
Handwritten mathematical equation recognition is a challenging problem in pattern recognition with significant applications in education technology, accessibility tools, and document digitization. This paper presents a comprehensive system for recognizing and solving handwritten mathematical equations using Convolutional Neural Networks (CNN). The proposed system integrates character segmentation using OpenCV contour detection, a deep CNN classifier trained on the MNIST dataset augmented with synthetic operator symbols, context-aware post-processing for disambiguation, and an equation parser supporting parentheses, exponentiation, and square root operations. The CNN architecture employs batch normalization, dropout regularization, and data augmentation techniques to achieve robust recognition across 18 symbol classes---digits 0--9, arithmetic operators (+, $-$, $\times$, $\div$), parentheses, exponentiation (\^{}), and square root ($\surd$). Experimental results demonstrate an overall classification accuracy of 99.22\% across all 18 classes. The system is deployed as a web application with a React-based frontend featuring a drawing canvas and a FastAPI backend for real-time inference. This paper details the methodology, system architecture, implementation, experimental results, and discusses the limitations and future directions for extending the system to handle more complex mathematical expressions.
\end{abstract}

\section{Introduction}

The recognition of handwritten mathematical equations has been an active area of research in pattern recognition and machine learning. With the increasing digitization of educational content and the growing need for accessible technology, automatic recognition of handwritten mathematical expressions has become increasingly important.

Handwritten equation recognition presents unique challenges compared to standard text recognition. Mathematical expressions contain not only alphanumeric characters but also various operators and symbols, each with distinct visual characteristics. Furthermore, the spatial relationships between symbols carry semantic meaning, making accurate segmentation crucial for correct interpretation.

This paper presents a complete end-to-end system for recognizing and solving handwritten mathematical equations. The system accepts an image of a handwritten equation, segments individual characters, classifies each character using a Convolutional Neural Network (CNN), applies context-aware corrections, parses the recognized sequence into a mathematical expression, and computes the result. The system supports an extended set of 18 symbol classes encompassing digits, basic arithmetic operators, parentheses, exponentiation, and square root.

\subsection{Contributions}

The main contributions of this work are:

\begin{itemize}
    \item An 18-class CNN architecture optimized for recognizing handwritten digits, arithmetic operators, parentheses, exponentiation, and square root symbols with 99.22\% accuracy
    \item A robust character segmentation algorithm using adaptive thresholding and contour detection with support for both dark and light backgrounds
    \item A context-aware post-processing module that resolves visual ambiguities between similar-looking symbols using geometric heuristics
    \item An equation parser supporting operator precedence, parenthesized sub-expressions, exponentiation, and square root evaluation
    \item A synthetic dataset generation pipeline producing diverse training samples for eight distinct mathematical operator classes
    \item A complete web-based application with a React frontend and FastAPI backend for real-time inference
\end{itemize}

\section{Literature Review}

\subsection{Handwritten Digit Recognition}

The MNIST dataset \cite{lecun1998mnist} has been the standard benchmark for handwritten digit recognition since its introduction in 1998. Early approaches used Support Vector Machines (SVM) and k-Nearest Neighbors (k-NN) algorithms, achieving accuracies around 98\% \cite{lecun1998gradient}.

The advent of deep learning revolutionized this field. LeCun et al. \cite{lecun1998gradient} introduced LeNet-5, a pioneering CNN architecture that achieved 99.05\% accuracy on MNIST. Subsequent improvements using deeper networks, dropout \cite{srivastava2014dropout}, and batch normalization \cite{ioffe2015batch} have pushed accuracies beyond 99.5\%.

\subsection{Mathematical Expression Recognition}

Mathematical expression recognition extends beyond digit recognition to include operators, variables, and complex spatial arrangements. Zanibbi and Blostein \cite{zanibbi2012recognition} provide a comprehensive survey of recognition techniques for mathematical notation.

Several approaches have been proposed for handwritten mathematical expression recognition:

\begin{itemize}
    \item \textbf{Grammar-based methods}: Use formal grammars to parse the spatial structure of expressions \cite{lavirotte1998mathematical}
    \item \textbf{Graph-based methods}: Represent symbols and relationships as graphs for structural analysis \cite{awal2014global}
    \item \textbf{End-to-end deep learning}: Use encoder-decoder architectures with attention mechanisms \cite{zhang2017watch}
\end{itemize}

\subsection{Character Segmentation}

Character segmentation is a critical preprocessing step for recognition systems. Traditional approaches use projection profiles, connected component analysis, and contour detection \cite{casey1996survey}. More recent methods employ deep learning for segmentation-free recognition \cite{shi2016end}.

\subsection{Research Gap}

While significant progress has been made in handwritten recognition, most systems focus either on digit recognition or complex mathematical typesetting requiring heavyweight models and large datasets such as CROHME \cite{mouchere2016icfhr2016}. There is a need for lightweight, deployable systems that can handle arithmetic equations---including grouped, exponentiated, and root expressions---with high accuracy and real-time performance. This work addresses this gap by providing a complete solution supporting 18 symbol classes with parentheses, exponentiation, and square root, while remaining compact enough for web deployment.

\subsection{Image Preprocessing}

The preprocessing pipeline prepares input images for segmentation:

\begin{enumerate}
    \item \textbf{Grayscale conversion}: Convert color images to single-channel grayscale
    \item \textbf{Gaussian blur}: Apply 3$\times$3 Gaussian kernel to reduce noise
    \item \textbf{Adaptive thresholding}: Binarize using Otsu's method with automatic threshold selection
    \item \textbf{Morphological operations}: Apply closing operation to connect broken strokes
\end{enumerate}

\subsection{Character Segmentation}

Individual characters are extracted using contour-based segmentation:

\begin{algorithmic}
\STATE \textbf{Input:} Binary image $I$
\STATE \textbf{Output:} List of character images $C$
\STATE $contours \gets$ FindContours($I$)
\STATE $boxes \gets \emptyset$
\FOR{each $contour$ in $contours$}
    \STATE $box \gets$ BoundingRect($contour$)
    \IF{MinArea $\leq$ Area($box$) $\leq$ MaxArea}
        \STATE $boxes \gets boxes \cup \{box\}$
    \ENDIF
\ENDFOR
\STATE Sort $boxes$ by x-coordinate (left to right)
\STATE $C \gets$ ExtractImages($I$, $boxes$)
\RETURN $C$
\end{algorithmic}

The segmentation pipeline is illustrated in Figure~\ref{fig:segmentation}. The system adaptively selects thresholding strategy based on mean pixel intensity to support both dark backgrounds (canvas-drawn) and light backgrounds (paper-scanned images).

Key architectural decisions include:

\begin{itemize}
    \item \textbf{Batch Normalization}: Applied after each convolutional layer to accelerate training and improve generalization
    \item \textbf{Dropout}: Used for regularization with rates of 0.25 after pooling layers and 0.5 in fully connected layers
    \item \textbf{L2 Regularization}: Applied to dense layers with factor 0.001
\end{itemize}

\subsection{Dataset Preparation}

The training dataset combines:

\begin{enumerate}
    \item \textbf{MNIST Dataset}: 60,000 training and 10,000 test images of handwritten digits (0--9)
    \item \textbf{Synthetic Operators}: 6,000 images per operator class for all eight operator symbols (+, $-$, $\times$, $\div$, (, ), \^{}, $\surd$) generated programmatically using OpenCV drawing primitives with variations in:
    \begin{itemize}
        \item Stroke thickness (1--3 pixels)
        \item Size (40--90\% of image)
        \item Position (random offset $\pm$3 pixels)
        \item Rotation ($\pm$15 degrees)
        \item Gaussian noise
    \end{itemize}
\end{enumerate}

The total training set comprises approximately 108,000 images (60,000 MNIST digits + 48,000 synthetic operator samples). Parentheses are rendered as arcs using OpenCV ellipse primitives, the caret symbol is drawn as two converging line segments, and the square root symbol is constructed from connected line segments forming the radical shape. Each synthetic sample is rendered on a 28$\times$28 canvas to match the MNIST image dimensions.

\subsection{Data Augmentation}

During training, real-time data augmentation is applied:

\begin{itemize}
    \item Random rotation ($\pm$15$^\circ$)
    \item Random scaling (85--115\%)
    \item Random translation ($\pm$3 pixels)
    \item Random brightness adjustment (80--120\%)
    \item Gaussian noise ($\sigma$ = 0.03)
\end{itemize}

\subsection{Training Configuration}

The model is trained with the following hyperparameters:

\begin{itemize}
    \item \textbf{Optimizer}: Adam with initial learning rate 0.001
    \item \textbf{Loss function}: Categorical cross-entropy
    \item \textbf{Batch size}: 128
    \item \textbf{Epochs}: 30 (with early stopping)
    \item \textbf{Learning rate schedule}: Reduce by 0.5 on plateau (patience=3)
\end{itemize}

\subsection{Equation Parsing}

The recognized character sequence undergoes a multi-stage parsing and evaluation pipeline:

\begin{enumerate}
    \item \textbf{Normalization}: The raw character sequence is transformed into a valid Python expression. The caret symbol (\^{}) is mapped to the exponentiation operator (\texttt{**}), the square root symbol ($\surd$) is converted to \texttt{sqrt()}, and alternative multiplication/division symbols ($\times$, $\div$) are normalized to \texttt{*} and \texttt{/} respectively. Multi-digit number sequences are preserved.
    \item \textbf{Validation}: The parser checks for balanced parentheses, valid character sequences, and potential division-by-zero conditions. Only characters from the set \{0--9, +, $-$, *, /, (, ), ., \^{}, space\} are permitted.
    \item \textbf{Safe Evaluation}: The validated expression is evaluated using a restricted execution environment that exposes only \texttt{math.sqrt}, \texttt{abs}, and \texttt{pow} as built-in functions, preventing arbitrary code execution while supporting the full range of recognized operations.
\end{enumerate}

\subsection{Context-Aware Post-Processing}

After CNN classification, a context-aware correction module refines predictions by analyzing the sequence of recognized symbols and their geometric properties. A common source of error is the visual similarity between the digit ``1'' and the division operator ``/''. When the predicted sequence contains a digit followed by ``1'' followed by another digit (e.g., ``3 1 5''), the system re-examines the character image of the ``1'' candidate. It computes the aspect ratio and dominant line angle of the bounding-box contents: a tall, narrow character with a near-vertical stroke is retained as ``1'', whereas a character whose principal axis is tilted significantly from vertical is reclassified as ``/''. This geometric heuristic significantly reduces misclassifications in division expressions without requiring additional model inference.

\subsection{Observations}

\begin{itemize}

    \item \textbf{Parentheses}: The lowest per-class accuracies were for ``('' (96.83\%) and ``)'' (97.00\%), attributed to visual similarity with digit ``0'' and the letter ``C''

% VII. LIMITATIONS

\section{Limitations}

Despite supporting 18 symbol classes, the current system has several limitations:

\subsection{Expression Complexity}

\begin{itemize}
    \item Limited to single-line equations; no support for fractions rendered as vertical stacks or multi-line systems of equations
    \item No support for variables (e.g., $x$, $y$), decimal points, or comparison operators (=, $<$, $>$)
    \item Exponentiation and square root are limited to single-level nesting; deeply nested expressions may not parse correctly
\end{itemize}

\subsection{Recognition Constraints}

\begin{itemize}
    \item Requires clear separation between characters for accurate contour-based segmentation
    \item Performance degrades with overlapping or connected characters
    \item Parentheses recognition accuracy (96--97\%) is lower than other classes due to visual similarity with digits and letters
\end{itemize}

\subsection{Technical Limitations}

\begin{itemize}
    \item Synthetic operator dataset may not capture all real-world handwriting variations
    \item No GPU optimization in the current deployment
    \item Requires stable internet connection for web-based usage
\end{itemize}

\section{Future Work}

Several directions for future improvement are identified:

\subsection{Extended Symbol Set}

    \item Support decimal points and negative number notation

% IX. CONCLUSION
% =============================================================================
\section{Conclusion}

This paper presented a complete system for recognizing and solving handwritten mathematical equations using Convolutional Neural Networks. The system achieves 99.22\% classification accuracy across 18 classes---digits 0--9, arithmetic operators (+, $-$, $\times$, $\div$), parentheses, exponentiation, and square root---by combining a well-designed CNN architecture with robust preprocessing, contour-based segmentation, and context-aware post-processing.

The key contributions include an 18-class CNN architecture with under 470K parameters, a synthetic data generation pipeline for eight mathematical operators, a context-aware disambiguation module using geometric heuristics, an equation parser supporting parenthesized sub-expressions and advanced operations, and a complete web-based deployment with real-time inference. The system demonstrates that high-accuracy handwritten equation recognition is achievable with a lightweight deep learning approach that extends beyond basic arithmetic to support grouped, exponentiated, and root expressions.

The modular architecture allows for future extensions to handle decimal numbers, variables, and more complex mathematical notation. The open-source nature of the project enables researchers and developers to build upon this work for educational technology, accessibility tools, and document digitization applications.
